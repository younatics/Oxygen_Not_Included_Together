# 합격 조건 — 대기복 이동 + 식물 게이트 계측 (커밋 4bb88ce8)

실행 **전에** 적는다. 이 세션에서 되돌린 4건 전부 이 습관 덕에 게임에 들어가기 전에 걸렸다.

## 대기복 — 셋 다 충족해야 합격

| # | 조건 | 어디서 읽나 |
|---|---|---|
| 1 | `state_compare` 에서 `Atmo_Suit` 셀 불일치 행이 **사라진다** | `runs/<label>/state_compare.txt` |
| 2 | 클라 `errors=0` (직전 실행과 동일) | 클라 HEALTH 행 |
| 3 | `suitApplied > 0` — 클라가 실제로 적용했다 | 클라 HEALTH 행 |

**1만 충족되면 합격이 아니다.** 우연히 그 실행에서 듀플이 수트를 안 집었을 수 있다.
`suitSent` 과 `suitApplied` 를 짝으로 읽는 이유: 보내기만 하고 안 붙는 것이 1번을 통과시킬 수 있다.

`suitSent > 0` 인데 `suitApplied == 0` → 수신·적용 경로 결함. 되돌리지 말고 그쪽을 본다.
`suitSent == 0` → 이 실행은 수트를 안 옮겼다. **판정 불가**, 조건 1의 통과를 근거로 쓰지 않는다.
`NoLockerId`/`NoMinionId` 가 양수면 id 해결 실패가 원인이다.

## 2차 (게이트 추가 후) — 측정된 것과, 다음 실행이 답해야 할 것

1차 실행이 답한 것 (2회, 빌드 `D32CEB34`):

```
soak01  호스트 sent=2  클라 recv=2  적용 0   UnequipFrom 예외 2
soak02  호스트 sent=5  클라 recv=5  적용 2   UnequipFrom 예외 3
```

유실 0. `EquipTo` 2/2 성공, `UnequipFrom` 5/5 NullReferenceException.
원인은 어셈블리 본문에 있었다 — `UnequipFrom` 첫 줄이 `GetAssignable(...Suit)` 이고 둘째 줄이
`assignable.Unassign()` 인데 **null 검사가 없다.** 게임은 chore 가 끝난 뒤에만 부르므로 이 경우가 없다.

`Atmo_Suit` 불일치 행: 직전 6개 배치(9회 실행) 11행 → 이번 2회 0행.

2차에서 판정할 것 (빌드 `suit03`):

| # | 조건 | 뜻 |
|---|---|---|
| 1 | `suitThrew == 0` | 게이트가 예외를 없앴다. **1 이상이면 아직 다른 경로가 있다** |
| 2 | `suitNoWorn > 0` | 그 5건이 실제로 "안 입은 듀플에게 온 벗기" 였음이 확정된다 |
| 3 | `suitApplied > 0` 유지 | 게이트가 되는 것까지 막지 않았다 |
| 4 | `Atmo_Suit` 행 0 유지 | |
| 5 | 클라 `errors=0` 유지 | |

`suitNoWorn == 0` 인데 `suitThrew == 0` 이면 그 실행이 벗기를 안 보낸 것이다 — **2번은 판정 불가**로
적고 1번의 0 을 성공 근거로 쓰지 않는다. 0 은 "없다"와 "못 본다"를 구분하지 못한다.

`suitNoStored` 는 수정이 아니라 정정이다. 1차의 `suitApplied` 는 "게임 함수가 안 던졌다"를 셌고,
`EquipTo` 는 락커가 비면 조용히 아무것도 안 한다 — 즉 옮기지 않은 것도 성공으로 셌다.
이제 `suitApplied` 는 게임이 옮길 것을 갖고 있었을 때만 오른다. **이 값이 1차보다 낮아질 수 있고,
그것은 회귀가 아니라 1차 숫자가 과대였다는 뜻이다.**

## 식물 — 계측이지 수정이 아니다. 합격/불합격이 아니라 원인 지목이다

| 관측 | 결론 |
|---|---|
| `plantSeen == 0` | 이 실행은 세션 중 아무것도 심지 않았다. **판정 불가** — 지난 실행의 `plant DIFFERENT 0` 과 같은 무의미한 0 |
| `plantNotWild > 0` | **원인 확정.** 심은 식물이 `IsWildPlanted()` 에서 거절된다 — 두 호스트 경로 어디에도 안 걸린다 |
| `plantNotBcast > 0` | 방송 게이트가 닫혀 있었다. 시점 문제이고 다른 수정이 필요하다 |
| `plantSeen > 0` 인데 위 둘 다 0, 그리고 `plantWild`/`plantPlot` 양수 | 호스트는 보냈다 → 결함은 클라 수신 쪽이다 |

`plantSeen` 은 **결정 앞**에 있다. 오늘 결함 하나가 세 번의 실행 동안 안 보인 건 모든 카운터가
결정 뒤에 있었기 때문이다.

## 이 실행이 답할 수 없는 것

- 시나리오에 **심기 동작이 없다**. `plantSeen` 은 콜로니가 스스로 심는 것에만 의존한다
  (STATUS 의 셀 53105, 실행마다 호스트 19 / 클라 18). 그것이 안 나오면 식물 쪽은 다시 판정 불가다.
- 실행 2회는 범주 합계의 변동(`circuit` 이 1→8 로 흔들린 폭)을 이길 수 없다.
  **전용 카운터로만 판정한다.** 합계 증감을 개선·회귀로 읽지 않는다.
