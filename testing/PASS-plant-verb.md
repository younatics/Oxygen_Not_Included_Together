# 합격 조건 — 심기 verb (검사를 만드는 변경이지 수정이 아니다)

실행 **전에** 적는다.

## 왜

식물 카운터를 넣은 4회 실행이 전부 `plantSeen=0` 이었다. 이건 "식물이 복제된다"가 아니라
**"아무것도 안 심었다"** 이고, 그래서 `plant DIFFERENT 0` 은 지금까지 세션 전부터 있던 458그루만
비교한 값이다. 식물 수정이 두 번 작성·배포·되돌려지는 동안 한 번도 판정된 적이 없다.

`ScenarioRunner` 에 `plant <n>` 을 넣고, 호스트에서만 심는다. 클라에서도 심으면 객체가 로컬로
생겨 격차가 가려진다 — 호스트 알만 부화시켜 클라 카운터가 0 이던 그 실수와 같은 모양이다.

경로는 게임 자신의 `SingleEntityReceptacle.ForceDeposit` 이다. 어셈블리에서 읽었다:
점유물 정리 → `SpawnOccupyingObject`(이 모드가 패치한 호스트 경로) → 배치 → 씨앗 파괴.
씨앗 태그는 화분이 **이미 주문한 것**을 쓰고, 없으면 그 화분이 받는 첫 씨앗을 쓴다. 지어내지 않는다.

## 1단계 — verb 가 실제로 심는가 (이게 먼저다)

| # | 조건 | 뜻 |
|---|---|---|
| 1 | 호스트 로그에 `OK plant :: sowed N of 2`, **N ≥ 1** | verb 가 동작한다 |
| 2 | 호스트 `plantSeen > 0` | 심기가 `Growing.OnSpawn` 에 도달했다 |
| 3 | 호스트 `errors = 0` | `ForceDeposit` 이 조용히 터지지 않았다 |

**N = 0 이면 여기서 멈춘다.** 그 경우 로그의 사유 분해(`plots seen / already occupied /
no seed they accept / no prefab`)를 읽고 verb 를 고친다. 이 콜로니에 빈 화분이 없으면
verb 가 아니라 시나리오가 화분을 먼저 지어야 한다.

## 2단계 — 1단계가 서면, 비로소 식물 복제를 판정할 수 있다

| 관측 | 결론 |
|---|---|
| `plantPlot > 0` 이고 클라 `plants` 가 호스트와 같아짐 | **복제된다.** 남은 결함은 없다 |
| `plantPlot > 0` 인데 클라 `plants` 가 낮음 | 호스트는 보냈다 → 결함은 **클라 수신** 쪽 |
| `plantNotWild > 0` | 심은 식물이 두 호스트 경로 어디에도 안 걸린다 — 원인 확정 |
| `plantNotBcast > 0` | 방송 게이트가 닫혀 있었다 — 시점 문제 |
| `plantSeen > 0` 인데 위 넷 다 0 | 화분 경로도 야생 경로도 아니다. 세 번째 경로를 찾아야 한다 |

`state_compare` 의 `plant` 행도 이제 의미가 생긴다: **`plant HOST-ONLY` 가 심은 수만큼 나오면
그것이 결함의 크기**다. 지금까지 이 행은 0 이었고 그 0 은 아무 뜻이 없었다.

## 이 변경이 답할 수 없는 것

- **야생 심기(`IsWildPlanted`) 는 여전히 안 건드린다.** 이 verb 는 화분 경로만 만든다.
  `plantWild` 가 계속 0 이어도 그건 그 경로를 안 밟은 것이지 고장 난 게 아니다.
- 식물 복제 자체는 **고치지 않는다.** 이건 판정 수단을 만드는 변경이다.
  행 수가 늘어날 수 있고, **늘어나는 것이 정상이다** — 안 보이던 결함이 보이기 시작하는 것이므로
  회귀로 읽지 않는다. 미리 적어둔다.
