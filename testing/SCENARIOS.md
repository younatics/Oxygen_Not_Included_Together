# 재현 시나리오

순서는 **결정력 ÷ 노력** 기준이다. S1–S2 는 코드를 한 줄도 안 고치고 돌리며,
둘 다 통과하지 못하면 나머지는 볼 필요가 없다.

각 시나리오는 **작은 신규 콜로니**에서 시작한다. 규모 의존 버그(#4·#12)를 먼저 배제해야
나머지 신호가 읽힌다.

공통 마무리:
```powershell
# 양쪽 PC 에서 같은 Label 로
.\collect-logs.ps1 -Role host   -Label S1
.\collect-logs.ps1 -Role client -Label S1
# 두 파일을 한 곳에 모아
python3 diff_logs.py runs\S1\host.log runs\S1\client.log
```

---

## S0 — 선행 점검 (PC 1대, 게임 1개)  ⭐ S1 보다 먼저

**목적** ① 빌드·모드 로드·LAN 바인딩이 되는지 ② AUDIT #3 을 **두 번째 PC 없이** 확정.

S1/S2 는 두 박스가 필요하지만, #3 의 *메커니즘*은 로그 하나로 증명된다
(README 0-b 참고 — 셀이 workable 해시에 안 들어가고 id 가 등록 순서로 배분된다).

1. PC-A 한 대에서 ONI 실행 → Mods 메뉴에서 dev 버전만 활성화, Workshop 버전 비활성화
2. 새 콜로니 생성 → LAN 호스트 시작 (클라 없이도 된다)
3. 타일 몇 칸 채굴 지정 → 복제인간이 캐게 둔다 → 종료
4. 판정:

```powershell
python selfcheck_log.py "$env:USERPROFILE\AppData\LocalLow\Klei\Oxygen Not Included\Player.log"
```

**기대 (버그가 살아있다면)**
- `A` 같은 `(prefab, type, cell)` 이 여러 id 를 받는다
- `B` 연속 id 구간이 여러 셀에 걸친다 → 셀이 해시에 없음이 확정
- exit code 1

**판정**
- A 또는 B → **#3 확정.** 두 번째 PC 는 이제 "얼마나 나쁜지" 를 재는 용도지, 확정용이 아니다
- 둘 다 0 → 이 실행에는 workable 등록이 거의 없었다는 뜻. 더 캐고 다시 돌린다

> 세션이 도는 동안 옆에서 보려면 별도 창에서 `.\watch-log.ps1`.

## S1 — 최소 참가 + 채굴 5칸  ⭐ 먼저 이것부터

**목적** AUDIT #3 (NetId 를 가변 float 에서 파생) 확정/반증. 계측 추가 없이.

1. PC-A: 새 콜로니 생성 → 즉시 일시정지 → LAN 호스트 시작
2. PC-B: PC-A 의 IP 로 접속, 세이브 전송·로드 완료까지 대기
3. 게임 재개, **타일 5칸만** 채굴 지정 → 복제인간이 다 캘 때까지 대기
4. 다시 일시정지 → 양쪽 로그 수집 → `diff_logs.py`

**기대 (버그가 살아있다면)**
- `1. NETID DIVERGENCE` 에 `Diggable` 항목이 **host≠client** 로 뜬다
- `3. REGISTRY LOOKUP FAILURES` 의 client 카운터가 0 이 아니다

**판정**
- mismatch > 0 → **#3 확정.** 최우선 수정 대상 확정
- mismatch = 0 → #3 은 이 경로에서 발동하지 않음. `Registered entity` 쪽 멀티셋 비교를 본다

## S2 — 캔 광석 개수를 눈으로 센다  ⭐ 로그조차 필요 없다

**목적** AUDIT #1 (클라에서 광석 2번 생성) 확정. **정량적이고 시각적이다.**

1. S1 상태 그대로
2. 양쪽에서 화면 좌상단 **자원 패널**의 해당 원소(예: Sandstone) 총량을 읽는다
3. 두 값을 비교한다

**기대** 클라 총량이 호스트의 **약 2배**. `ResourceSyncer` 가 비활성이라 클라는 자기
월드에서 총량을 계산하고, 그 월드에는 광석이 두 번 생성되어 있다.

**판정**
- 클라 ≈ 2× 호스트 → **#1 확정.** 수정은 2줄
- 두 값이 같다 → #1 반증. `WorldDamagePatch` 경로를 다시 추적해야 한다

> 보조 확인: 채굴한 셀을 클릭해 아이템 목록을 본다. 같은 셀에 동일 원소 더미가
> 2개면 확정적이다.

## S3 — 파이프에 가스/액체 흘리기 (LAN 전용 버그)

**목적** AUDIT #2·#3 (전체상태/델타 패킷이 1000B 를 넘어 신뢰성 없는 조각으로 분해).

1. 가스 펌프 1개 + 파이프 **50칸 이상** 깔고 가동
2. 2분 방치
3. 양쪽에서 같은 파이프 구간을 클릭해 **내용물(원소·질량·온도)** 비교

**기대** 클라의 파이프 내용이 고착되거나 호스트와 다르다. 시간이 갈수록 악화되고
스스로 복구되지 않는다 (4.5초 전체 재전송조차 같은 조각화 경로를 타므로).

**대조군** 같은 시나리오를 **Steam 세션**으로 반복 → Steam 은 정상이면 원인이
Riptide 의 1000바이트 한도임이 확정된다 (`ConduitFlowSyncer` 주석은 Steam 1200B 를 가정).

## S4 — 식물 25개 임계

**목적** AUDIT #2 (전체상태 주기 패킷의 크기 절벽).

1. 식물이 **25개 미만**인 상태에서 양쪽 성장률 비교 → 일치해야 한다
2. 야생 식물 포함 **30개 이상**이 되도록 심는다 (`PlantTracker` 는 야생도 전부 넣는다)
3. 5분 방치 후 다시 비교

**기대** 25개 근처를 넘어가면서 클라 성숙도가 호스트와 벌어지고 **다시 수렴하지 않는다.**
오류 메시지는 없다 — 그래서 위험하다.

---

## S5 — 크리터

**목적** AUDIT #5 (크리터 생명주기 전부 미복제) 확정.

1. 해치 2마리 + 인공부화기
2. 알이 생기고 부화할 때까지 (1~2 사이클) 방치
3. 양쪽 크리터 수 / 알 유무 / 인공부화기 내용 비교

**기대** 클라의 크리터 개체수가 **참가 시점에 동결**. 새로 태어난 것이 안 보이고,
호스트에서 죽은 개체가 클라에는 **움직이지 않는 채로 남아 있다.**

## S6 — 큰 콜로니 참가 (규모 의존)

**목적** AUDIT #4 (하드싱크당 월드 N+1회 동기 저장 → 호스트 동결 → "Host Lost")
와 #12 (로드가 타임아웃보다 길면 로드 루프).

1. 수백 사이클 된 세이브를 호스트로 로드 (없으면 S1 콜로니를 빠르게 키운다)
2. `TimeoutSeconds` 를 **기본 30** 으로 되돌린다
3. PC-B 접속

**기대**
- 호스트가 세이브를 뜨는 동안 **수 초~수십 초 완전 정지** (마우스도 안 먹는다)
- 클라가 타임아웃 → "Host Lost"
- 또는 클라가 세이브를 **두 번 이상** 다운로드 (로드가 30초를 넘겨서)

**대조군** `TimeoutSeconds = 120` 으로 올려 재시도 → 참가가 성공하면 #12 확정.
S1 의 작은 콜로니에서는 재현되지 않아야 한다 → 규모 의존성 입증.

## S7 — 재접속 (알려진 함정)

**목적** 재접속 경로가 애초에 동작하는지 확인.

1. 정상 세션 중 PC-B 의 랜선을 5초 뽑았다 꽂는다
2. 클라가 재접속을 시도하는지 관찰

**기대 — 이건 이미 확정된 버그다.** `RiptideClient.CleanupRiptide()` 가 끊길 때마다
`ServerIp/ServerPort` 를 `127.0.0.1:7777` 로 덮어쓰고 `ReconnectToSession()` 이 그 값을 읽는다.
→ 재접속은 **localhost:7777** 로 가서 절대 성공하지 않는다.
로그에서 `Connecting to 127.0.0.1:7777` 을 찾으면 확정.

## S8 — 하드싱크

**목적** AUDIT #7 (추측 타이머 종료 · 클라 안 멈춤 · 호스트 안 재개).

1. 세션 중 하드싱크 실행
2. **양쪽 사이클 타이머/시계를 동시에 관찰**
3. 완료 후 호스트의 일시정지 상태 확인

**기대**
- 호스트는 멈췄는데 **클라의 시간은 계속 흐른다** (클라가 곧 받을 스냅샷보다 앞서간다)
- 하드싱크 후 **호스트가 일시정지에 갇혀** 사람이 직접 풀어야 한다

## 기록 규칙

`runs/<Label>/` 에 다음이 함께 있어야 나중에 재현이 된다:
- `host.log`, `client.log`, `host.meta.json`, `client.meta.json` (모드 DLL sha256 포함 — **두 박스가 같아야 한다**)
- `notes.md` — 무엇을 했고 무엇을 봤는지 3줄
- `diff.json` (`diff_logs.py --json diff.json`)

수정 후 재측정할 때는 **같은 시나리오·같은 Label + `-fixed` 접미사**로 돌려
`diff_logs.py` 의 exit code 가 1 → 0 으로 바뀌는지 본다. 그게 회귀 게이트다.
